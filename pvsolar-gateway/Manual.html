Introdução

Conhecendo o pvSolar Gateway

O pvSolar Gateway é uma solução profissional de monitoramento de inversores solares projetada para ambientes industriais. Ele atua como um gateway inteligente que coleta dados de inversores solares via Modbus TCP/RTU e os publica em brokers MQTT com segurança de nível militar (TLS 1.3, mTLS).

Segurança Empresarial

TLS 1.3, mTLS com certificados X.509, ACLs por tópico e autenticação por dispositivo.

Multi-Fabricante

Suporte nativo a Fronius, Growatt, SMA, Huawei via SunSpec Modbus (IEEE 1547-2018).

Edge Computing

Armazenamento local SQLite com store-and-forward para até 72 horas de dados.

Cloud Ready

Integração nativa com AWS IoT Core e Azure IoT Hub via MQTT seguro.

Licenciamento Open Core

O core do gateway é open source (GPLv3). Funcionalidades premium como AWS IoT, Azure IoT Hub e relatórios avançados estão disponíveis sob licença comercial.

Fluxo de Dados

1
Coleta de Dados

Os drivers Modbus realizam polling periódico nos inversores solares, lendo registradores SunSpec ou específicos do fabricante.

2
Normalização

Os dados brutos são convertidos para um padrão unificado (InverterData) com campos padronizados para potência, tensão, corrente, energia e status.

3
Processamento Edge

Dados são armazenados localmente no SQLite e processados para cálculos de Performance Ratio (PR), eficiência e anomalias.

4
Publicação MQTT

Dados são publicados em tópicos MQTT estruturados com criptografia TLS 1.3 e autenticação por certificado.

5
Integração Cloud

Dados são sincronizados com AWS IoT Core, Azure IoT Hub ou broker MQTT local para análise e visualização.

Instalação

Guia completo de instalação

Instalação com Docker (Recomendado)

Recomendado para Produção

Docker é a forma mais segura e fácil de implantar o pvSolar Gateway em produção.

1
Pré-requisitos

Instale Docker Engine 20.10+ e Docker Compose 2.0+:

# Ubuntu/Debian sudo apt update sudo apt install docker.io docker-compose-plugin # Verificar instalação docker --version docker compose version
2
Clonar Repositório
git clone https://github.com/your-org/pvsolar-gateway.git cd pvsolar-gateway/docker
3
Configurar Gateway
# Criar diretório de configuração mkdir -p config # Copiar configuração de exemplo cp ../config/gateway.example.yaml config/gateway.yaml # Editar configuração nano config/gateway.yaml
4
Gerar Certificados TLS
# Criar diretório de certificados mkdir -p certs # Gerar CA (Certificate Authority) openssl req -x509 -nodes -days 365 -newkey rsa:2048 \ -keyout certs/ca.key -out certs/ca.crt \ -subj "/CN=pvSolar CA" # Gerar certificado do servidor openssl req -nodes -newkey rsa:2048 \ -keyout certs/server.key -out certs/server.csr \ -subj "/CN=mqtt.pvsolar.local" openssl x509 -req -in certs/server.csr -CA certs/ca.crt \ -CAkey certs/ca.key -CAcreateserial -out certs/server.crt -days 365 # Gerar certificado do cliente (gateway) openssl req -nodes -newkey rsa:2048 \ -keyout certs/client.key -out certs/client.csr \ -subj "/CN=pvsolar-gateway-001" openssl x509 -req -in certs/client.csr -CA certs/ca.crt \ -CAkey certs/ca.key -CAcreateserial -out certs/client.crt -days 365
5
Iniciar Stack
# Iniciar todos os serviços docker compose up -d # Verificar status docker compose ps # Acompanhar logs docker compose logs -f pvsolar-gateway
6
Verificar Instalação
# Dashboard Web http://localhost:5000 # Grafana http://localhost:3000 # MQTT Broker mosquitto_sub -h localhost -p 1883 -t "pvsolar/#"

Instalação Manual (Linux)

Requer Conhecimento Técnico

Este método é recomendado apenas para desenvolvedores experientes ou ambientes sem suporte a Docker.

# Instalar dependências do sistema sudo apt update sudo apt install python3 python3-pip python3-venv sqlite3 # Criar usuário dedicado sudo useradd -r -s /bin/false pvsolar sudo mkdir -p /opt/pvsolar /etc/pvsolar /var/lib/pvsolar /var/log/pvsolar # Clonar e instalar cd /opt/pvsolar git clone https://github.com/your-org/pvsolar-gateway.git . python3 -m venv venv source venv/bin/activate pip install -r requirements.txt # Configurar sudo cp config/gateway.example.yaml /etc/pvsolar/gateway.yaml sudo nano /etc/pvsolar/gateway.yaml # Criar serviço systemd sudo tee /etc/systemd/system/pvsolar.service << 'EOF' [Unit] Description=pvSolar Gateway After=network.target [Service] Type=simple User=pvsolar Group=pvsolar WorkingDirectory=/opt/pvsolar ExecStart=/opt/pvsolar/venv/bin/python -m pvsolar -c /etc/pvsolar/gateway.yaml Restart=always RestartSec=10 [Install] WantedBy=multi-user.target EOF # Ativar e iniciar sudo systemctl daemon-reload sudo systemctl enable pvsolar sudo systemctl start pvsolar sudo systemctl status pvsolar

Configuração

Arquivo de configuração gateway.yaml

O pvSolar Gateway utiliza um arquivo YAML para configuração. Abaixo estão os principais parâmetros:

Configuração do Gateway

gateway: name: "solar-site-001" # Identificador único location: "São Paulo, BR" # Localização física timezone: "America/Sao_Paulo"

Configuração MQTT

mqtt: broker: "mqtt.example.com" port: 8883 # Porta TLS use_tls: true tls: ca_cert: "/etc/pvsolar/certs/ca.crt" client_cert: "/etc/pvsolar/certs/client.crt" client_key: "/etc/pvsolar/certs/client.key" tls_version: "1.3" client_id: "pvsolar-gateway-001" topics: publish: "pvsolar/{site_id}/telemetry" status: "pvsolar/{site_id}/status"

Configuração de Inversores

inverters: - id: "fronius-001" name: "Fronius GEN24 Plus 8.0" driver: "fronius" # sunspec|fronius|growatt|sma|huawei connection: host: "192.168.1.100" port: 502 unit_id: 1 polling_interval: 5.0 # segundos
Configuração Completa

Consulte o arquivo config/gateway.example.yaml para todos os parâmetros disponíveis.

Configuração MQTT

Comunicação segura com broker MQTT

Estrutura de Tópicos

Tópico Direção Descrição QoS
pvsolar/{site}/telemetry/{inv} Publish Dados de telemetria do inversor 1
pvsolar/{site}/status Publish Status do gateway (online/offline) 1 (retain)

Segurança MQTT

TLS 1.3

Criptografia de ponta a ponta com cifras AES-256-GCM eChaCha20-Poly1305.

mTLS

Autenticação mútua com certificados X.509 por dispositivo.

ACLs por Tópico

Controle granular de acesso por tópico por dispositivo.

Exemplo: Configuração Mosquitto

# /etc/mosquitto/mosquitto.conf # Listener TLS na porta 8883 listener 8883 cafile /etc/mosquitto/certs/ca.crt certfile /etc/mosquitto/certs/server.crt keyfile /etc/mosquitto/certs/server.key tls_version tlsv1.2 require_certificate true use_identity_as_username true # Desabilitar listener plaintext # listener 1883 # allow_anonymous false

Integração com pvbrowser

Bridge para HMI SCADA

O pvSolar Gateway inclui um bridge nativo para o pvbrowser, permitindo visualização em tempo real dos dados solares em interface SCADA profissional.

Configuração

pvbrowser: enabled: true socket_port: 5050 shared_memory: true update_interval: 1.0

Protocolo de Comunicação

O bridge utiliza um protocolo TCP simples com a seguinte estrutura:

# Header: [protocol_version, msg_type, payload_length] header = struct.pack('!BBH', protocol_version, msg_type, payload_length) payload = json.dumps(data).encode('utf-8') message = header + payload

Exemplo: Python Client

import socket import json import struct def connect_to_gateway(host='localhost', port=5050): sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM) sock.connect((host, port)) while True: # Receber header header = sock.recv(4) version, msg_type, length = struct.unpack('!BBH', header) # Receber payload payload = sock.recv(length) data = json.loads(payload) print(f"Inversor: {data['inverter_id']}") print(f"Potência: {data['data']['power']['ac_power']} W")

Solução de Problemas

Common issues and resolutions

Não consigo conectar ao inversor

Causas possíveis:

  • Endereço IP incorreto do inversor
  • Porta Modbus incorreta (padrão: 502)
  • Unit ID incorreto
  • Firewall bloqueando conexão
  • Modbus desabilitado no inversor

Solução:

# Testar conectividade ping 192.168.1.100 # Testar porta Modbus nc -zv 192.168.1.100 502 # Testar com pymodbus python3 -c " from pymodbus.client import ModbusTcpClient client = ModbusTcpClient('192.168.1.100', port=502) result = client.read_holding_registers(0, 10, slave=1) print(result) "
Falha na conexão MQTT

Causas possíveis:

  • Certificados TLS inválidos ou expirados
  • CN (Common Name) do certificado não confere
  • Porta TLS incorreta (deve ser 8883)
  • Broker MQTT não aceita conexões TLS

Solução:

# Verificar certificado openssl s_client -connect mqtt.example.com:8883 # Testar conexão MQTT mosquitto_sub -h mqtt.example.com -p 8883 \ --cafile ca.crt --cert client.crt --key client.key \ -t "test" -v # Verificar logs do broker docker compose logs mosquitto
Dados inconsistentes ou zerados

Causas possíveis:

  • Modo float vs integer incorreto
  • Fatores de escala (scale factors) incorretos
  • Endereços de registradores errados
  • Inversor em modo standby ou fault

Solução:

  • Verificar se o driver está correto (sunspec, fronius, growatt)
  • Consultar manual Modbus do fabricante
  • Usar sunspec driver para inversores certificados
  • Verificar status do inversor: status: "running"
Gateway não inicia

Causas possíveis:

  • Arquivo de configuração YAML inválido
  • Dependências Python faltando
  • Porta já em uso
  • Permissões de arquivo incorretas

Solução:

# Validar configuração python3 -c "from pvsolar.core.config import load_config; load_config('config/gateway.yaml')" # Verificar dependências pip install -r requirements.txt # Verificar porta lsof -i :5000 # Verificar logs docker compose logs pvsolar-gateway journalctl -u pvsolar -n 100
pvbrowser não recebe dados

Causas possíveis:

  • Pocket socket desabilitado
  • Porta 5050 bloqueada por firewall
  • pvbrowser não conectado ao gateway

Solução:

# Verificar se a porta está aberta netstat -tlnp | grep 5050 # Testar conexão telnet localhost 5050 # Verificar configuração grep -A5 "pvbrowser" config/gateway.yaml
Armazenamento edge lotado

Causas possíveis:

  • Conexão com cloud/broker instável
  • Buffer max_buffer_hours muito alto
  • Sincronização automática falhando

Solução:

# Verificar tamanho do buffer sqlite3 /var/lib/pvsolar/edge.db "SELECT COUNT(*) FROM telemetry WHERE synced=0;" # Limpar registros antigos sqlite3 /var/lib/pvsolar/edge.db "DELETE FROM telemetry WHERE synced=1 AND created_at < strftime('%s','now') - 259200;" # Ajustar configuração edge: store_and_forward: max_buffer_hours: 48 # Reduzir de 72 para 48

Perguntas Frequentes

Dúvidas comuns dos usuários

Qual o custo do pvSolar Gateway?

O core do pvSolar Gateway é gratuito e open source sob licença GPLv3. Funcionalidades premium como AWS IoT Core, Azure IoT Hub, relatórios avançados e suporte técnico 24/7 estão disponíveis sob licença comercial. Entre em contato para valores.

Posso usar com inversores de outros fabricantes?

Sim! O driver sunspec suporta qualquer inversor certificado SunSpec (IEEE 1547-2018). Isso inclui a maioria dos fabricantes modernos como SolarEdge, GoodWe, Sungrow, entre outros. Para fabricantes específicos, podemos desenvolver drivers customizados.

Quantos inversores posso monitorar?

O gateway foi projetado para monitorar centenas de inversores simultaneamente. O limite real depende do hardware e intervalo de polling. Para 100 inversores com polling de 5 segundos, um servidor com 4GB de RAM é suficiente. Para instalações maiores, recomendamos múltiplos gateways com balanceamento de carga.

O gateway funciona offline?

Sim! O pvSolar Gateway foi projetado para operar em ambientes com conectividade intermitente. O sistema de store-and-forward armazena até 72 horas de dados localmente (SQLite) e sincroniza automaticamente quando a conexão é restabelecida.

Preciso de conhecimento em programação?

Para uso básico, não. A configuração é feita via arquivo YAML e o gateway funciona com configurações padrão. Para personalizações avançadas, desenvolvimento de drivers ou integrações customizadas, conhecimento em Python é recomendado. Oferecemos treinamento e consultoria.
