Introducao
Visao geral do pvSolar Scheduler

O pvSolar Scheduler e o sistema de agendamento de tarefas do ecossistema pvSolar. Ele permite criar, gerenciar e executar tarefas automatizadas com diferentes tipos de agendamento e politicas de retry.

Agendamento Flexivel
Intervalo, cron, diario, semanal, mensal ou uma vez.
Retry Automatico
Politica de retentativas configuravel por tarefa.
Prioridades
4 niveis: low, normal, high, critical.
Tags
Organize tarefas por categoria ou servico.
Historico
Registro completo de execucoes com retencao.
API REST
API completa para integracao e automacao.

Banco de Dados
PostgreSQL (opcional)

A persistencia e opcional: com database.enabled: false o servico roda somente em memoria (comportamento original). Quando ativa, as tarefas, o estado de execucao (run_count, status, next_run) e o historico de execucoes sao gravados em PostgreSQL e sobrevivem a reinicios do servico.

1. Configurar a URL
# Opcao A: config/scheduler.yaml database: enabled: true url: "postgresql+asyncpg://postgres:senha@localhost:5432/pvsolar_scheduler" # Opcao B: variavel de ambiente (tem prioridade sobre o YAML) set PVSOLAR_DATABASE_URL=postgresql+asyncpg://postgres:senha@localhost:5432/pvsolar_scheduler
2. Criar o banco (uma vez)
python scripts\create_databases.py
3. Iniciar o servico
uvicorn src.api.app:app --host 0.0.0.0 --port 8009 # O schema e criado automaticamente no startup (create_tables: true)

Comportamento no startup

  • Cria as tabelas caso nao existam (idempotente)
  • Carrega tarefas e historico do banco para a memoria (hydrate)
  • Insere linhas para as tarefas declaradas apenas no YAML
  • Aplica a retencao configurada (task_history_max) no banco

Gravacao (write-through)

  • POST/PUT/DELETE de tarefas grava na mesma requisicao
  • Cada execucao concluida grava o resultado e o novo estado da tarefa
  • POST /api/tasks/{id}/run persiste run_count, status e next_run
TabelaConteudo
tasksCadastro da tarefa (configuracao) e estado de execucao
task_resultsHistorico de execucoes: status, duracao, saida e erro
VariavelDescricao
PVSOLAR_DATABASE_URLURL do banco; ao ser definida ativa a persistencia
PVSOLAR_DB_ENABLEDForca database.enabled (1/true/0/false)
PVSOLAR_CONFIGCaminho de um YAML de configuracao alternativo (padrao: config/scheduler.yaml)
PVSOLAR_TEST_DB_URLRoda os testes contra PostgreSQL real (use sempre o banco *_test, criado pelo script)

Semantica: o banco e a fonte de verdade para as tarefas que possuem linha. Alterar uma tarefa no YAML so passa a valer quando a linha for removida (delete via API) ou em desenvolvimento com scripts\reset_database.py.

Scripts utilitarios

python scripts\create_databases.py # cria o banco (uma vez) python scripts\reset_database.py --yes # dropa todas as tabelas (dev)

Para validar a persistencia em testes: python -m pytest tests/ -v (usa SQLite por padrao). Para rodar contra o PostgreSQL real, aponte para o banco de testes dedicado - os testes dropam o schema a cada execucao:

set PVSOLAR_TEST_DB_URL=postgresql+asyncpg://postgres:senha@localhost:5432/pvsolar_scheduler_test python -m pytest tests/ -v
