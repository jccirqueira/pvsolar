pvSolar Auth
Authentication & Authorization Module
======================================

OVERVIEW
--------
Authentication, authorization, and multi-tenant management for pvSolar ecosystem.
Provides JWT-based authentication with refresh tokens, role-based access control (RBAC),
API key management, and tenant isolation.

DATABASE (PostgreSQL)
---------------------
Persistence is optional: with database.enabled=false the service runs purely
in memory (original behaviour, used by unit tests).

Setup:
  1. Copy config/auth.example.yaml to config/auth.yaml and set database.url
     (or export PVSOLAR_DATABASE_URL=postgresql+asyncpg://user:senha@host:5432/pvsolar_auth)
  2. .\venv\Scripts\python.exe scripts\create_databases.py
  3. Start the service - schema is created automatically on startup

On startup the service loads users/tenants/roles from PostgreSQL into memory
(hydrate) and creates the seed admin only when the database is empty.
Every mutation is written through to the database, so accounts, lockout state
(API brute-force protection), tenants and roles survive restarts.

DEFAULT ROLES
-------------
- super_admin: All permissions
- admin: Manage users, data, settings
- operator: Monitor, alerts, ack alarms
- viewer: Read-only access
- api: API access only

PERMISSIONS
-----------
- read: Read data
- write: Write/modify data
- delete: Delete data
- admin: System administration
- manage_users: Create/edit/delete users
- manage_roles: Create/edit/delete roles
- manage_tenants: Create/edit/delete tenants
- manage_api_keys: Create/revoke API keys
- view_audit_log: View audit log

FEATURES
--------
- Optional PostgreSQL persistence (async SQLAlchemy, survives restarts)
- JWT access/refresh token pair
- Token revocation (blacklist)
- Session management (multi-device)
- API key management
- Rate limiting per IP
- Password hashing (PBKDF2-SHA256 + salt)
- Account lockout after failed attempts (15-minute window)
- Password policy enforcement
- Multi-tenant with feature flags
- User limits per tenant
- RBAC with role hierarchy

PRODUCTION
----------
- Use HTTPS (TLS termination via reverse proxy)
- Change JWT secret key (256-bit minimum)
- Change bcrypt rounds (12+ recommended)
- Set proper CORS origins
- Configure rate limits for production
- Enable database.enabled with a dedicated PostgreSQL user (least privilege)
- Back up the pvsolar_auth database regularly
- Rotate JWT signing keys periodically
