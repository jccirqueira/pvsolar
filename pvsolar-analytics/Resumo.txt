1. CONTEXTO E OBJETIVO DO PROJETO
================================================================================

O projeto "pvSolar Analytics" é uma plataforma AI/ML de analytics para
monitoramento de inversores solares. Consome dados do pvSolar Gateway via
MQTT para fornecer manutenção preditiva, detecção de anomalias, previsão
de energia e scoring de performance.

Modelo de Negócio: Open Core
- Core (GPLv3): Gratuito — analytics básico, anomalias, performance
- Premium (Comercial): LSTM avançado, multi-tenant, relatórios, alertas

Parceria com: pvSolar Gateway (coleta de dados)
Stack: Python 3.11.9, FastAPI, SQLAlchemy, PyTorch, scikit-learn

4.7 ML/ANOMALY/detector.py (5 detectores)
-------------------------------------------
Detecção de anomalias em tempo real.

1. IsolationForestDetector — Multivariado (sklearn)
2. ZScoreDetector — Univariado baseado em desvio padrão
3. RollingMeanDetector — Detecção de mudanças súbitas
4. SPCDetector — Statistical Process Control (gráfico X-bar)
5. ThresholdDetector — Limites simples min/max

AnomalyDetector combina todos os detectores.
Resultado: AnomalyResult com severity (low/warning/error/critical)

4.8 ML/MAINTENANCE/predictor.py
---------------------------------
Predição de manutenção com Gradient Boosting.

Feature Extraction (MaintenanceFeatureExtractor):
- Statistical: mean, std, min, max, skewness, kurtosis
- Trend: slope, acceleration, momentum
- Stability: CV, within_1std, sign_changes
- Cross-metric: power-temp corr, power-eff corr
- Operational: uptime %, fault %, fault_code_changes

Prediction (MaintenancePredictor):
- 3 horizontes: 7d, 30d, 90d
- Risk levels: LOW, MEDIUM, HIGH, CRITICAL
- Recomendações automáticas baseadas no risco
- Feature importance para explicabilidade

4.9 ML/FORECAST/predictor.py
------------------------------
Previsão de energia com LSTM.

Feature Extraction (ForecastFeatureExtractor):
- Temporal: hour_sin/cos, day_of_week, month, is_weekend
- Rolling: 3h, 6h, 12h, 24h windows
- Lag: 1, 2, 3, 6, 12, 24 hours
- Trend: slope, acceleration, momentum
- Weather proxy: irradiance, temp correlation
- Calendar: holiday, season

Model (LSTMEnergyModel):
- Input projection → LSTM 2 camadas → Attention → Output
- Hidden: 64, Dropout: 0.2
- Training: 100 epochs, Adam, MSE loss

Fallback (SimpleForecaster):
- Trend + seasonal decomposition
- Sem dependência de PyTorch

4.10 ML/PERFORMANCE/calculator.py
-----------------------------------
Cálculo de performance de inversores.

Métricas (pesos):
- Performance Ratio (PR): 35%
  PR = (Energia Real / Energia Teórica) × 100
- Calendar Energy Factor (CEF): 25%
  CEF = (Energia Real / Energia Esperada) × 100
- Availability: 25%
  Availability = (Tempo Rodando / Tempo Total) × 100
- Efficiency: 15%
  η = (AC Power / DC Power) × 100

Grades: A+ (≥95), A (≥90), B+ (≥85), B (≥80), C+ (≥75), C (≥70), D (≥60), F

4.11 ML/PERFORMANCE/benchmark.py
----------------------------------
Benchmarking entre inversores.

- Fleet Percentile — Ranking percentil no conjunto total
- vs Fleet Average — Diferença % da média da frota
- vs Peer Average — Diferença % do grupo de pares
- vs Historical — Comparação com histórico do inversor

Peer Groups: agrupamento por modelo, capacidade, região.

9. ALGORITMOS ML
================================================================================

Detecção de Anomalias:
- Isolation Forest: detecção multivariada sem supervisão
- Z-Score: detecção univariada (threshold: 3.0)
- Rolling Mean: janela móvel com threshold adaptativo
- SPC (X-bar): controle estatístico de processos
- Threshold: limites fixos min/max configuráveis

Manutenção Preditiva:
- Gradient Boosting (sklearn): classificação binária
- 3 horizontes: 7d (curto), 30d (médio), 90d (longo)
- Features: 4 categorias, ~50 features por inversor
- Risk levels: LOW → MEDIUM → HIGH → CRITICAL

Previsão de Energia:
- LSTM (PyTorch): sequence-to-sequence
- Arquitetura: Input → LSTM 2 camadas → Attention → Output
- Hidden: 64, Dropout: 0.2, Epochs: 100
- Fallback: SimpleForecaster (trend + seasonal)
- Horizontes: 1h, 24h, 7d

Performance Scoring:
- PR (Performance Ratio): energia real vs teórica
- CEF (Calendar Energy Factor): energia real vs esperada
- Availability: tempo de operação vs tempo total
- Efficiency: conversão DC→AC
- Score ponderado: 35% PR + 25% CEF + 25% Avail + 15% Eff
- Grades: A+ a F

10. PROBLEMAS ENCONTRADOS E SOLUÇÕES
================================================================================

10.1 structlog event parameter conflict
    Problema: structlog conflita com parâmetro nomeado `event`
    Solução: Usar `event_type` em vez de `event`

10.2 SQLAlchemy Column defaults
    Problema: Defaults não setam em objetos Python até commit
    Solução: Setar valores padrão explicitamente no __init__

10.3 API test mocking
    Problema: FastAPI TestClient precisa de mock para store
    Solução: Usar fixtures com mock para cada rota

10.4 datetime.now(timedelta.utc)
    Problema: `datetime.now(timedelta.utc)` é inválido
    Solução: Usar `datetime.now(timezone.utc)`

10.5 PyTorch not installed
    Problema: LSTMEnergyModel falha sem PyTorch
    Solução: SimpleForecaster como fallback estatístico

10.6 LSTM batch dimension
    Problema: Modelo espera 3D (batch, seq, features), recebe 2D
    Solução: Adicionar batch dimension em _prepare_input

10.7 Forecast feature type
    Problema: features.get() retorna None em vez de array
    Solução: Usar np.asarray() com dtype=float
