Introdução

Conhecendo o pvSolar Analytics

O pvSolar Analytics é uma plataforma AI/ML completa para analytics de inversores solares. Consome dados do pvSolar Gateway via MQTT e aplica algoritmos de machine learning para fornecer insights acionáveis sobre a saúde, performance e manutenção dos inversores.

Anomaly Detection

5 algoritmos: Isolation Forest, Z-Score, Rolling Mean, SPC, Threshold. Detecção multivariada e univariada em tempo real.

Predictive Maintenance

Gradient Boosting para predição de falhas em 7, 30 e 90 dias. Feature engineering com ~50 features por inversor.

Energy Forecasting

LSTM com PyTorch para previsão de energia. Previsão horária, diária e semanal com attention mechanism.

Performance Scoring

PR, CEF, disponibilidade e eficiência. Benchmarking entre inversores com ranking percentil.

Licenciamento Open Core

O core do analytics é open source (GPLv3). Funcionalidades premium como LSTM avançado, multi-tenant e relatórios estão disponíveis sob licença comercial.

Módulos de Machine Learning

5 módulos ML completos

Anomaly Detection

  • Isolation Forest — Detecção multivariada sem supervisão
  • Z-Score — Detecção univariada baseada em desvio padrão
  • Rolling Mean — Detecção de mudanças súbitas na média móvel
  • SPC (X-bar) — Controle estatístico de processos
  • Threshold — Limites simples min/max configuráveis

Predictive Maintenance

  • Gradient Boosting — Classificação binária (sklearn)
  • 3 horizontes: 7d, 30d, 90d
  • ~50 features por inversor
  • Risk levels: LOW → MEDIUM → HIGH → CRITICAL
  • Recomendações automáticas baseadas no risco

Energy Forecasting

  • LSTM — PyTorch com attention mechanism
  • Arquitetura: Input → LSTM 2 camadas → Attention → Output
  • Hidden: 64, Dropout: 0.2, Epochs: 100
  • Fallback: SimpleForecaster (trend + seasonal)
  • Horizontes: 1h, 24h, 7d

Performance Scoring

  • PR (Performance Ratio): 35% peso
  • CEF (Calendar Energy Factor): 25% peso
  • Availability: 25% peso
  • Efficiency: 15% peso
  • Benchmarking percentil entre inversores

Algoritmos ML

Detalhes técnicos dos algoritmos

Anomaly Detection — Isolation Forest

O Isolation Forest isola observações selecionando aleatoriamente um feature e um split value. Anomalias requerem menos splits para serem isoladas.

# Parâmetros padrão contamination = 0.1 # 10% esperado como anomalias n_estimators = 100 max_samples = 256 # Features monitoradas metrics = ["ac_power", "temperature", "efficiency", "ac_frequency"]

Predictive Maintenance — Gradient Boosting

Gradient Boosting treina árvores sequencialmente, cada uma corrigindo os erros da anterior. Features de ~50 dimensões por inversor.

# Parâmetros padrão n_estimators = 100 max_depth = 5 learning_rate = 0.1 subsample = 0.8 # Horizontes de predição horizons = { "7d": probabilidade_curto_prazo, "30d": probabilidade_medio_prazo, "90d": probabilidade_longo_prazo, } # Risk levels risk = { "LOW": prob_30d < 0.15, "MEDIUM": 0.15 <= prob_30d < 0.40, "HIGH": 0.40 <= prob_30d < 0.70, "CRITICAL": prob_30d >= 0.70, }

Energy Forecasting — LSTM

Long Short-Term Memory (LSTM) é uma Rede Neural Recorrente capaz de aprender dependências de longo prazo em séries temporais.

# Arquitetura Input (10 features) → Projection (64) → LSTM (2 camadas, 64 hidden) → Attention → Output (forecast_horizon) # Treinamento optimizer = Adam(lr=0.001) loss = MSELoss() epochs = 100 batch_size = 32

Performance Scoring — Fórmulas

PR = (E_real / E_teorica) × 100 CEF = (E_real / E_esperada) × 100 Availability = (t_running / t_total) × 100 η = (P_AC / P_DC) × 100 Score = 0.35×PR + 0.25×CEF + 0.25×Avail + 0.15×η

Grades

  • A+ — ≥ 95%
  • A — ≥ 90%
  • B+ — ≥ 85%
  • B — ≥ 80%
  • C+ — ≥ 75%
  • C — ≥ 70%
  • D — ≥ 60%
  • F — < 60%

Solução de Problemas

Problemas comuns e soluções

PyTorch não instalado

Se LSTM não funcionar, o sistema usa automaticamente o SimpleForecaster (fallback estatístico). Para LSTM completo, instale: pip install torch --index-url https://download.pytorch.org/whl/cpu

Erro de import: structlog event parameter

structlog conflita com parâmetro nomeado event. Use event_type em vez de event ao chamar logger.

datetime.now timezone

Use sempre datetime.now(timezone.utc) em vez de datetime.now(timedelta.utc) —后者 é inválido.
