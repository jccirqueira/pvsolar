Requisitos Previos
O que voce precisa ter instalado
Python 3.11
Linguagem principal dos backends. Baixe em python.org. Marque "Add Python to PATH" na instalacao.
Node.js 18+
Necessario apenas para o pvSolar Web (frontend). Baixe em nodejs.org.
Git
Para baixar os codigos. Baixe em git-scm.com.
Docker (Opcional)
Se quiser rodar via container. Baixe em docker.com.
PostgreSQL (Opcional)
Para persistir usuarios (Auth) e tarefas (Scheduler) entre reinicios. Sem ele, esses dois servicos rodam apenas em memoria.
Como verificar se esta instalado
Abra o Prompt de Comando (Windows) ou Terminal (Mac/Linux) e digite:
# Verificar Python python --version # Deve mostrar: Python 3.11.x # Verificar Node.js node --version # Deve mostrar: v18.x.x ou superior # Verificar Git git --version # Deve mostrar: git version 2.x.x

PostgreSQL - Persistencia
Opcional: dados que sobrevivem a reinicios
Faca antes do Passo 4
O pvSolar Auth (usuarios, tenantes, chaves de API) e o pvSolar Scheduler (tarefas e historico) persistem em PostgreSQL. Sem configurar o banco eles funcionam normalmente em memoria, mas os dados se perdem ao reiniciar.
1. Ter um PostgreSQL rodando
# Verificar se ja existe um servico local pg_isready # Em duvida? Instale em postgresql.org/download/windows ou use Docker: docker run -d --name pvsolar-pg -p 5432:5432 -e POSTGRES_PASSWORD=pvsolar_dev postgres:17
2. Configurar a URL de conexao
# pvsolar-auth/config/auth.yaml (e o mesmo bloco em pvsolar-scheduler) # O arquivo YAML e lido automaticamente no start do servico. database: enabled: true url: "postgresql+asyncpg://postgres:senha@localhost:5432/pvsolar_auth" # Alternativa via variavel de ambiente (tem prioridade sobre o YAML): set PVSOLAR_DATABASE_URL=postgresql+asyncpg://postgres:senha@localhost:5432/pvsolar_auth
3. Criar os bancos (uma unica vez)
cd pvsolar-auth venv\Scripts\activate python scripts\create_databases.py cd ..\pvsolar-scheduler python scripts\create_databases.py # Cria: pvsolar_auth + pvsolar_auth_test # pvsolar_scheduler + pvsolar_scheduler_test
4. Pronto - inicie os servicos normalmente
# O schema e criado sozinho no primeiro start (create_tables: true). # O usuario inicial admin/admin123 so e criado se o banco estiver vazio # (nunca duplica, mesmo reiniciando varias vezes).
Bancos _test sao recriados a cada execucao dos testes
Os testes de persistencia dropam e recriam o schema. Por isso o script cria o banco *_test junto: aponte PVSOLAR_TEST_DB_URL apenas para ele e nunca para o banco de producao.

Onde entra o pvBrowser?
Explicacao completa sobre o pvBrowser

O que e o pvBrowser?

O pvBrowser e uma biblioteca/protocolo para criar telas SCADA/HMI. Pense nele como um "Google Forms" mas para paineis de controle industriais. Ele permite criar telas visuais que mostram dados em tempo real de uma planta solar.

Nao e necessario instalar pvBrowser separadamente!
O pvBrowser ja esta integrado dentro do pvSolar SCADA. Quando voce instala e roda o pvSolar SCADA (porta 5000), o pvBrowser ja vem junto.

Como ele se conecta ao ecossistema

pvBrowser (protocolo TCP) │ ▼ pvSolar SCADA (porta 5000) │ ├──── Le dados do Gateway via API (porta 8000) ├──── Le dados do Analytics via API (porta 8001) └──── Le dados do Auth via API (porta 8007)

6 Telas Prontas
Dashboard, Inversores, Clima, Alarmes, Performance e Sistema.
14 Tipos de Widgets
Botoes, graficos, medidores, indicadores, tabelas e mais.

Comunicacao via protocolo pvBrowser na porta 5000.

Docker / VPS
Stack completa: 13 servicos + PostgreSQL + Mosquitto + Caddy

O docker-compose.yml da raiz e o ponto de entrada unico do ecossistema. Ele sobe os 13 servicos (cada um com seu docker/Dockerfile), o PostgreSQL com os bancos ja criados, o broker MQTT e o Caddy como porta unica de entrada.

Mesma origem, zero CORS
O Web e construido com URLs relativas (/auth, /gateway, ...) e servido pelo Caddy em http://localhost - todas as chamadas ficam na mesma origem e nenhum CORS e disparado. As portas dos servicos ficam publicadas apenas em 127.0.0.1 para debug local.

Volumes e backup
Os dados vivem nos volumes pgdata, caddy_data, caddy_config, reports-output e backup-data. docker compose down preserva tudo; docker compose down -v apaga o Postgres. Faça dump antes:

SCADA fica fora do Caddy
O SCADA fala o protocolo TCP do pvBrowser (nao HTTP) e nao passa pelo proxy: conecte o cliente pvBrowser direto na porta 5000 do host. O Web, por sua vez, nao consome o SCADA por HTTP.

Baixe em prometheus.io e configure para scraping:
# prometheus.yml scrape_configs: - job_name: 'pvsolar' scrape_interval: 15s static_configs: - targets: ['localhost:8010'] metrics_path: '/metrics'
Instalar Grafana
Baixe em grafana.com. Adicione o Prometheus como Data Source:
Configuracao
Settings > Data Sources > Add > Prometheus > URL: http://localhost:9090
Criar painel Grafana
Use o namespace pvsolar_ para queries:
# Energia total dos inversores sum(pvsolar_gateway_messages_received) # Inversores online pvsolar_gateway_inverter_count # Uptime do sistema pvsolar_gateway_uptime_seconds # Anomalias detectadas pvsolar_analytics_anomalies_detected # Alertas ativos pvsolar_alert_active_alerts
Problemas Comuns e Solucoes
Duvidas frequentes
"Port is already in use" / "Porta em uso"
Solucao: Outro programa esta usando a porta. Feche o programa ou mude a porta no arquivo .yaml do projeto.
"ModuleNotFoundError" / "Modulo nao encontrado"
Solucao: O ambiente virtual nao esta ativo. Execute: venv\Scripts\activate antes de rodar qualquer comando.
"Connection refused" / "Conexao recusada"
Solucao: Verifique se o Gateway (porta 8000) esta rodando. Todos os outros projetos dependem dele.
"Syntax error" / "Erro de sintaxe"
Solucao: Verifique se esta usando Python 3.11 ou superior. Execute: python --version
"npm not found" / "npm nao encontrado"
Solucao: Instale o Node.js em nodejs.org. O npm vem junto.
SCADA sem dados / telas vazias
Solucao: Verifique se o Gateway esta rodando e conectado aos inversores. Confirme o IP no arquivo gateway.yaml.
Web Dashboard nao carrega
Solucao: Verifique se todos os backends estao rodando. O Web precisa de pelo menos Auth e Gateway funcionando.
Erro "No label names were set"
Solucao: Erro do Prometheus Client. Verifique se o Exporter esta configurado corretamente no exporter.yaml.
