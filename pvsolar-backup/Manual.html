Introducao
Visao geral do pvSolar Backup

O pvSolar Backup e o sistema de backup automatizado do ecossistema pvSolar. Ele permite fazer backup de todos os dados, configuracoes e banco de dados dos servicos pvSolar com agendamento flexivel e politicas de retencao.

6 Backends
Local, S3, FTP, SMB, Azure Blob, Google Cloud Storage.
Agendamento
Hourly, daily, weekly, monthly ou cron customizado.
Compressao
ZIP, GZip, TAR, TAR.GZ para economizar espaco.
Retencao
Max backups, idade maxima, minimo garantido.
Restore
Restauracao completa com inspecao de conteudo.
API REST
API completa para integracao e automacao.

Instalacao
Guia passo a passo
Clonar o repositorio
git clone https://github.com/pvsolar/pvsolar-backup.git cd pvsolar-backup
Criar ambiente virtual
python -m venv venv venv\Scripts\activate
Instalar dependencias
pip install -r requirements.txt
Configurar
cp config/backup.example.yaml config/backup.yaml # Editar config/backup.yaml # Precedencia: PVSOLAR_CONFIG=/caminho.yaml > config/backup.yaml > defaults
Executar testes
python -m pytest tests/ -v
Iniciar API
uvicorn src.api.app:app --host 0.0.0.0 --port 8008
Configuracao
Arquivo backup.yaml
storage: type: "local" local_path: "./backups" compression: "tar.gz" retention: max_backups: 30 max_age_days: 90 min_keep: 5 schedule: enabled: true frequency: "daily" time: "02:00" data_sources: database_path: "data/" config_path: "config/" api: port: 8008
ParametroPadraoDescricao
storage.typelocalTipo de backend de armazenamento
compressiontar.gzTipo de compressao
retention.max_backups30Maximo de backups
retention.max_age_days90Idade maxima em dias
schedule.frequencydailyFrequencia de agendamento
schedule.time02:00Horario do backup
api.port8008Porta da API

Docker
Deploy containerizado
# Recomendado: compose da raiz do ecossistema (docker-compose.yml) docker compose up -d backup # Variante de config com URLs internas: docker/config/backup.yaml # Legado: compose do proprio projeto docker-compose up -d docker-compose logs -f pvsolar-backup docker-compose down
Producao
Melhores praticas
  • Configure S3 ou storage remoto para backups offsite
  • Defina politicas de retencao adequadas
  • Ative notificacoes para falhas
  • Use criptografia para dados sensiveis
  • Teste procedimentos de restore regularmente
  • Monitore espaco em disco
  • Use HTTPS para a API em producao
Dica de Seguranca
Mantenha sempre pelo menos 1 backup em local diferente da planta (3-2-1 rule).
